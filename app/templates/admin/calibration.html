Reference datasets

A dataset's credibility tier caps the confidence any field calibrated against it can render: Tier C never renders High. A dataset marked pending verification is also capped at Moderate, however dense its data — so a seeded or freshly uploaded extract is useful immediately without overstating its own authority. Clear the flag only once you have checked the numbers against the source.

Per-agent field bindings

Each row binds one numeric field an agent emits to a dataset. The output_field is the JSON key the agent is asked to return in its METRICS block — adding a config here changes what the agent is asked for on its next run, with no deploy. A config with no dataset bound renders the field raw.

{# ── Drift monitor ────────────────────────────────────────────────────── #}

Drift monitor

Verified outcome reports grouped by cohort, against the current reference distribution. A cohort is only reweighted once it clears its min_reports_to_reweight gate — the optimal-stopping rule that stops us chasing noise from the first few reports. Reweighting blends reports at parity with reference observations and returns the dataset to pending verification, because its numbers are then no longer exactly what the cited source published.

Upload reference rows

CSV header: soc_group,metro,seniority,p10,p50,p90,mean,sample_size,as_of_date. Only soc_group and p50 are required; metro defaults to national and seniority to any, which is what the cohort ladder relaxes down to. Rows upsert on cohort, so re-uploading a corrected extract replaces rather than duplicates.
