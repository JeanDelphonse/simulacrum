Config source
config/agents.json — 49 agents, 71KB. This PRD is the human-readable specification of that configuration. The JSON file is the machine-readable implementation. They must stay in sync.
Scope
Part A: Documents every agent's prerequisites, data dependencies, integration routing, signal taxonomy, and triggered-by relationships as derived from agents.json. Part B: Specifies the GCC Agent Network tab visualization — a multi-layer graph showing agents as nodes and dependencies as flow lines connecting agents within and across layers.
Design principle
The agent network is a directed acyclic graph (DAG). Prerequisites define the edges. The orchestrator walks the DAG to determine dispatch eligibility. The GCC Agent Network tab renders this DAG visually so the user understands why agents run in a specific order and how data flows between them.

6. GCC Agent Network Tab — Visualization Spec
The Agent Network tab renders the 49-agent DAG as a visual graph. Each agent is a node. Each prerequisite is a directed edge (flow line). The graph is organized by layer (5 horizontal bands). The user sees how data flows from rate_card through all 5 layers.
6.1 Layout
Element
Specification
Layer bands
5 horizontal bands stacked vertically. Each band represents one layer. L1 at the top (leftmost in the flow), L5 at the bottom. Band height scales to agent count. Band background: subtle layer-colored tint (L1 teal 4%, L2 gold 4%, L3 purple 4%, L4 coral 4%, L5 navy 4%).
Layer labels
Left side of each band: layer number (L1-L5) + layer name ('Active Income') in 14px bold. Agent count badge: '11 agents' in a pill.
Agent nodes
Each agent is a rounded rectangle (120×60px). Agent name (12px bold). Layer badge (10px pill). Status icon: green check (completed), teal spinner (in progress), grey lock (locked/prerequisites not met), outline circle (eligible but not yet dispatched). Background: white with subtle border. Hover: teal border + shadow.
Node positioning
Within each band, agents are positioned left-to-right in execution order (layer_index). Agents with no prerequisites sit on the left. Agents with prerequisites sit to the right of their dependencies. Auto-layout via dagre or d3-dag.
Flow lines
SVG path lines connecting source node (right edge) to target node (left edge). Line color: teal for completed connections, grey dashed for pending. Arrow heads at the target end. Line width: 2px. Hover over a line: tooltip shows what data flows ('Rate card tiers → workshop pricing').
Cross-layer lines
Lines that cross layer bands are highlighted with a slightly thicker stroke (3px) and a gradient color transitioning from the source layer color to the target layer color. These are the most important connections — they show how income layers build on each other.

8. Functional Requirements
Agent Configuration
FR-MAP-01  config/agents.json is the single source of truth for all 49 agents. The orchestrator reads this file at startup. Every agent property (prerequisites, integrations, signals, cost, model) is defined in this file. No agent behavior is hardcoded in application code.
FR-MAP-02  The prerequisite DAG has 30 directed edges. The orchestrator walks the DAG before each dispatch: an agent is eligible only if all its prerequisites have completed at least once AND its layer is unlocked AND it is not currently in progress.
FR-MAP-03  5 agents are cold start chain members (cold_start_chain: true). They execute sequentially via Celery chain on Cycle 1 only. After Cycle 1, all agents are dispatched via Bayesian scoring.
FR-MAP-04  5 agents are triggered (triggered_by field). They dispatch immediately when a specific signal fires, regardless of Bayesian score: consulting_proposal (reply with interest), sow_template (proposal signed), agreement_template (SOW signed), negotiation_script (price objection), speaker_fee_rider (speaking confirmed).
Integration Routing
FR-MAP-05  9 integrations used across 32 agents: Internal Email (10), Apollo (8), Stripe (6), PandaDoc (5), Kajabi (5), ConvertKit (5), Cal.com (3), LinkedIn (2), Alpaca (1). Before dispatching an agent, the orchestrator verifies that all required integrations are connected and tokens are valid.
FR-MAP-06  If a required integration is disconnected, the agent is skipped with status='integration_missing'. The GCC shows a warning: '[Agent] could not run — [Integration] is not connected. Connect in Settings → Integrations.'
Agent Network Visualization
